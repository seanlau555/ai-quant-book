## LTCM：諾貝爾獎得主的致命假設

1998 年，長期資本管理公司（LTCM）擁有兩位諾貝爾經濟學獎得主、華爾街最頂尖的數學家、以及 1250 億美元的資產。

他們的模型精妙絕倫，基於一個核心假設：**市場收益服從正態分佈**。

按正態分佈計算，他們的策略一天虧損超過 1% 的概率是 10 萬分之一。一年 252 個交易日，理論上要 400 年才會遇到一次。

**然後俄羅斯債務違約了。**

1998 年 8 月 21 日一天，LTCM 虧損 5.5 億美元。接下來的一個月，他們虧損了 46 億美元——幾乎全部資本。按正態分佈，這種事件發生的概率是 10 的負 27 次方，大約是宇宙誕生以來每秒發生一次都不可能遇到。

但它發生了。

**問題出在哪裏？**

1. **市場不是正態分佈**：真實市場是"厚尾分佈"，極端事件的頻率遠超正態分佈預測
2. **相關性會突變**：正常時期資產相關性低，危機時所有資產相關性飆升到 1
3. **波動率會聚集**：大跌之後往往還是大跌，不是獨立的"拋硬幣"

LTCM 的教訓：**不是模型不夠精確，是數學假設從根本上錯了。**

這一課的目標：讓你理解金融數據的真實特性，避免用"拋硬幣"的數學去分析市場。

## 3.1 時間序列基礎

### 序列 vs IID 假設

傳統統計學假設數據是 **IID (Independent and Identically Distributed)**：獨立同分布。
- 獨立：今天的數據和昨天無關
- 同分布：每天的數據來自同一個分佈

**金融數據幾乎從不滿足 IID 假設**：

```python
import numpy as np

# IID 數據：拋硬幣
coin_flips = np.random.choice([0, 1], size=100)  # 每次獨立，概率恆定

# 金融數據：今天的價格依賴昨天
prices = [100]
for _ in range(99):
    # 今天的價格 = 昨天的價格 + 隨機變動
    prices.append(prices[-1] * (1 + np.random.normal(0, 0.02)))
```

**為什麼這很重要？**
- 如果你用 IID 假設建模，會低估連續虧損的概率
- 真實市場有"慣性"：漲了容易繼續漲，跌了容易繼續跌

### 滯後 (Lag) 與自相關

**自相關 (Autocorrelation)**：當前值與過去值的相關性。

**紙上計算示例**：

假設連續 5 天的收益率是：+2%, -1%, +3%, +2%, -2%

| 今天 (t) | 昨天 (t-1) |
|---------|-----------|
| -1% | +2% |
| +3% | -1% |
| +2% | +3% |
| -2% | +2% |

觀察規律：
- 昨天漲，今天有時漲有時跌 → 自相關接近 0（隨機）
- 如果昨天漲今天大概率漲 → 自相關為正（動量）
- 如果昨天漲今天大概率跌 → 自相關為負（均值迴歸）

**SPY（標普 500 ETF）的日收益自相關通常接近 0**（例如 2010-2020 年約為 0.02）——幾乎為 0，説明美股日收益接近隨機遊走，短期難以預測。具體數值因樣本期間而異。

**解讀**：
- 自相關接近 0 → 過去對未來預測價值低（弱式有效市場）
- 自相關顯著為正 → 動量效應（趨勢跟隨可能有效）
- 自相關顯著為負 → 均值迴歸效應

<details>
<summary>💻 代碼實現（工程師參考）</summary>

```python
import pandas as pd

def calculate_autocorrelation(series, lag=1):
    """計算滯後 lag 期的自相關係數"""
    return series.autocorr(lag=lag)

# 示例：SPY (S&P 500 ETF) 日收益率的自相關
returns = prices_series.pct_change().dropna()

print(f"滯後1期自相關: {calculate_autocorrelation(returns, 1):.3f}")
print(f"滯後5期自相關: {calculate_autocorrelation(returns, 5):.3f}")
```

</details>

### 平穩性檢驗

**平穩性**：統計特性（均值、方差）不隨時間變化。

```python
from statsmodels.tsa.stattools import adfuller

def check_stationarity(series, name="Series"):
    """ADF 檢驗：判斷序列是否平穩"""
    result = adfuller(series.dropna())
    print(f"{name}:")
    print(f"  ADF 統計量: {result[0]:.4f}")
    print(f"  p-value: {result[1]:.4f}")
    print(f"  結論: {'平穩 ✓' if result[1] < 0.05 else '非平穩 ✗'}")

# 價格序列通常非平穩
check_stationarity(prices_series, "價格序列")

# 收益率序列通常平穩
check_stationarity(returns_series, "收益率序列")
```

**為什麼要檢驗平穩性？**
- 大多數統計模型假設輸入是平穩的
- 對非平穩序列建模會產生"偽迴歸"
- **解決方案**：用收益率（差分）代替價格

## 3.2 收益的數學定義

### 簡單收益 vs 對數收益

**📝 紙上計算**：

假設 AAPL 從 $100 漲到 $110：

```
簡單收益 = (110 - 100) / 100 = 10%
對數收益 = ln(110/100) = ln(1.1) ≈ 9.53%
```

**為什麼量化常用對數收益？** 看下面的例子：

**可加性問題**（用計算器驗證）：

| | Day 1 | Day 2 | 總收益 |
|--|-------|-------|-------|
| 價格 | $100 → $110 | $110 → $100 | $100 → $100 |
| 簡單收益 | +10% | -9.09% | **0%** |
| 直接相加 | | | 10% - 9.09% = 0.91% ❌ |
| 對數收益 | +9.53% | -9.53% | **0%** |
| 直接相加 | | | 9.53% - 9.53% = 0% ✅ |

> **關鍵洞察**：漲 10% 再跌回來，簡單收益不等於 0（因為基數變了），但對數收益等於 0。

**結論**：對數收益可以直接相加，簡單收益必須連乘。當你需要計算 100 天的累計收益時，對數收益只需 100 次加法，簡單收益需要 100 次乘法。

| 特性 | 簡單收益 | 對數收益 |
|-----|---------|---------|
| 可加性 | ✗ 多期收益不能直接相加 | ✓ 多期收益可以直接相加 |
| 對稱性 | ✗ 漲10%再跌10%≠0 | ✓ 更接近對稱 |
| 正態假設 | 較難滿足 | 更接近正態 |

### 累計收益計算

**📝 紙上計算**：

連續 5 天的日收益率：+1%, -2%, +3%, +1%, -1%

**簡單收益累計**（連乘）：
```
(1+0.01) × (1-0.02) × (1+0.03) × (1+0.01) × (1-0.01) - 1
= 1.01 × 0.98 × 1.03 × 1.01 × 0.99 - 1
= 1.0194 - 1 ≈ 1.94%
```

**對數收益累計**（直接相加）：
```
0.01 + (-0.02) + 0.03 + 0.01 + (-0.01) = 2%
```

兩種方法結果接近，但對數收益計算更簡單。

### 年化收益率

**📝 紙上計算**：

假設 60 個交易日賺了 5%，年化是多少？

```
年化收益 = (1 + 5%)^(252/60) - 1
        = 1.05^4.2 - 1
        = 1.227 - 1
        ≈ 22.7%
```

**為什麼是 252？** 美股一年約 252 個交易日（365 天 - 週末 - 節假日）。

**常見錯誤**：
- ❌ 直接把月收益 × 12 當年化（忽略複利）
- ❌ 用日曆天數而非交易日（應該用 252 不是 365）
- ❌ 忽略手續費後再年化

<details>
<summary>💻 代碼實現（工程師參考）</summary>

```python
def cumulative_return(returns, method='simple'):
    """計算累計收益"""
    if method == 'simple':
        return (1 + returns).prod() - 1  # 連乘
    else:
        return returns.sum()  # 直接相加

def annualize_return(total_return, days, trading_days_per_year=252):
    """年化收益率"""
    years = days / trading_days_per_year
    return (1 + total_return) ** (1 / years) - 1

# 示例：60 天賺了 5%
ann_return = annualize_return(0.05, 60)
print(f"年化收益率: {ann_return:.2%}")  # ≈ 23.5%
```

</details>

## 3.3 風險的數學定義

### 方差與標準差

**📝 紙上計算**：

假設 5 天的日收益率：+1%, -2%, +3%, 0%, -1%

**Step 1：計算均值**
```
均值 = (1 - 2 + 3 + 0 - 1) / 5 = 0.2%
```

**Step 2：計算方差**（每個值與均值的差的平方的平均）
```
方差 = [(1-0.2)² + (-2-0.2)² + (3-0.2)² + (0-0.2)² + (-1-0.2)²] / 5
     = [0.64 + 4.84 + 7.84 + 0.04 + 1.44] / 5
     = 14.8 / 5 = 2.96 (%²)
```

**Step 3：計算標準差**（波動率）
```
日波動率 = √2.96 ≈ 1.72%
```

**Step 4：年化**
```
年化波動率 = 日波動率 × √252 ≈ 1.72% × 15.87 ≈ 27.3%
```

**波動率的直覺含義**：

| 年化波動率 | 典型資產 | 一年可能的波動範圍（68%概率） |
|-----------|---------|---------------------------|
| 15% | 大盤股（SPY） | -15% 到 +15% |
| 30% | 科技股（TSLA） | -30% 到 +30% |
| 80% | 加密貨幣（BTC） | -80% 到 +80% |

**記住這個公式**：年化波動率 = 日波動率 × √252 ≈ 日波動率 × 16

<details>
<summary>💻 代碼實現（工程師參考）</summary>

```python
def calculate_volatility(returns, annualize=True, trading_days=252):
    """計算波動率（標準差）"""
    daily_vol = returns.std()
    if annualize:
        return daily_vol * np.sqrt(trading_days)
    return daily_vol

# 示例
daily_returns = pd.Series([0.01, -0.02, 0.03, 0, -0.01])
annual_vol = calculate_volatility(daily_returns)
print(f"年化波動率: {annual_vol:.2%}")
```

</details>

### 協方差與相關性

**直覺理解**：

相關係數衡量兩個資產"是否同漲同跌"：

| 相關係數 | 含義 | 例子 |
|---------|------|-----|
| +1 | 完全同步：A 漲 B 必漲 | 同行業股票（AAPL vs MSFT） |
| 0 | 無關：A 漲跌與 B 無關 | 黃金 vs 科技股 |
| -1 | 完全相反：A 漲 B 必跌 | 股票 vs VIX（恐慌指數） |

**實際市場中的相關性**（參考值）：

| 資產對 | 正常時期相關性 | 危機時期相關性 |
|-------|--------------|--------------|
| AAPL vs MSFT | +0.7 | +0.9 |
| SPY vs TLT (債券) | -0.3 | -0.5 或 +0.8 |
| SPY vs GLD (黃金) | +0.1 | -0.2 |

**危機時期的"相關性飆升"**：正常時期不相關的資產，危機時可能突然相關性飆到 0.9。這就是 LTCM 馬失前蹄的原因——他們假設相關性穩定。

**多智能體視角**：Portfolio Agent 的核心工作就是尋找低相關資產構建組合，但 Risk Agent 必須考慮"危機時相關性飆升"的風險。

<details>
<summary>💻 代碼實現（工程師參考）</summary>

```python
def analyze_correlation(returns_a, returns_b):
    """分析兩個資產的相關性"""
    corr = returns_a.corr(returns_b)
    print(f"相關係數: {corr:.3f}")

    if corr > 0.7:
        print("→ 高度正相關：漲跌同步，分散效果差")
    elif corr < -0.3:
        print("→ 負相關：天然對沖，適合組合")
    else:
        print("→ 低相關：有分散風險的價值")
```

</details>

### 分佈假設的危險性

**正態分佈假設會害死你。** 這是 LTCM 事件的核心教訓。

**📝 紙上計算**：

假設 SPY 年化波動率 20%，日波動率約 1.26%（= 20% / √252）。

在正態分佈下：
- 日跌幅超過 1σ (1.26%) 的概率 = 16%（正常）
- 日跌幅超過 2σ (2.52%) 的概率 = 2.3%（每月 0.5 次）
- 日跌幅超過 3σ (3.78%) 的概率 = 0.13%（每 3 年 1 次）
- 日跌幅超過 4σ (5.04%) 的概率 = 0.003%（每 125 年 1 次）

**但實際發生了什麼？**

| 日期 | 事件 | SPY 單日跌幅 | 按正態分佈的"幾σ事件" | 理論上多少年一遇 |
|-----|------|------------|---------------------|----------------|
| 2020-03-16 | COVID崩盤 | -12.0% | 9.5σ | 10^20 年 |
| 2008-10-15 | 金融危機 | -9.0% | 7.1σ | 10^12 年 |
| 2011-08-08 | 美國降級 | -6.7% | 5.3σ | 1500萬年 |
| 2018-02-05 | 波動率崩盤 | -4.1% | 3.3σ | 4年 |

**結論**：正態分佈説"10^20 年一遇"的事件，實際上每隔幾年就發生一次。

**這就是"厚尾分佈"的威力**——極端事件發生的頻率遠超正態分佈預測。如果你的風控模型假設正態分佈，你必定會在某個"黑天鵝"事件中爆倉。

## 3.4 金融時間序列的特殊性

### 厚尾分佈 (Fat Tails)

**兩個關鍵指標**：

1. **偏度 (Skewness)**：分佈是否對稱
   - 偏度 = 0 → 對稱（漲跌幅度差不多）
   - 偏度 < 0 → 左偏（暴跌比暴漲多）
   - **股票市場偏度通常是 -0.5 到 -1**，説明暴跌風險大於暴漲機會

2. **峯度 (Kurtosis)**：尾部有多"厚"
   - 峯度 = 3 → 正態分佈
   - 峯度 > 3 → 厚尾（極端事件比正態分佈預測的多）
   - **股票市場峯度通常是 5-10**，遠超正態分佈的 3

| 指標 | 正態分佈 | SPY 實際 | 含義 |
|-----|---------|---------|------|
| 偏度 | 0 | -0.7 | 暴跌更劇烈 |
| 峯度 | 3 | 8 | 極端事件頻繁 |

**厚尾對策略的影響**：
- 止損必須考慮跳空風險（隔夜暴跌可能跳過你的止損價）
- VaR 模型會嚴重低估風險
- 需要用 Expected Shortfall (CVaR) 替代 VaR

<details>
<summary>💻 代碼實現（工程師參考）</summary>

```python
def analyze_tail_risk(returns):
    """分析尾部風險"""
    skew = returns.skew()  # 偏度
    kurt = returns.kurtosis()  # 峯度（減3後的）

    print(f"偏度: {skew:.3f} {'(負偏，小心暴跌)' if skew < -0.5 else ''}")
    print(f"峯度: {kurt+3:.3f} {'(厚尾！)' if kurt > 0 else ''}")
```

</details>

### 波動聚集 (Volatility Clustering)

**GARCH 效應**：大波動之後往往還是大波動，小波動之後往往還是小波動。

**直覺理解**：

回想 2020 年 3 月的 COVID 暴跌：
- 3月9日：SPY 跌 7.6%
- 3月12日：SPY 跌 9.5%
- 3月16日：SPY 跌 12.0%

暴跌不是獨立的"拋硬幣"——一旦開始暴跌，往往會連續暴跌。這就是波動聚集。

**波動率的自相關高達 0.7-0.9**，遠高於收益率的自相關（約 0）。這意味着：
- 收益率幾乎不可預測（隨機遊走）
- **波動率是可預測的**（明天的波動率很可能和今天相近）

**實戰意義**：
- 波動率可預測性 > 收益率可預測性
- 趨勢 Agent 應該在低波動期建倉，高波動期減倉
- Risk Agent 應該根據近期波動率動態調整止損

<details>
<summary>💻 代碼實現（工程師參考）</summary>

```python
def detect_volatility_clustering(returns, window=20):
    """檢測波動聚集"""
    rolling_vol = returns.rolling(window).std()
    vol_autocorr = rolling_vol.autocorr(lag=1)
    print(f"波動率的滯後1期自相關: {vol_autocorr:.3f}")
```

</details>

### 非平穩性與結構性斷裂 (Regime Shift)

市場會在不同"狀態"之間切換，每個狀態有不同的統計特性：

| Regime | 特徵 | 適合策略 |
|--------|------|---------|
| **牛市** | 低波動、正收益、低相關 | 動量、買入持有 |
| **震盪** | 中波動、收益接近0 | 均值迴歸 |
| **危機** | 高波動、負收益、高相關 | 減倉、對沖 |

**結構性斷裂的典型案例（近似值）**：

> 注：下表為常見量級示意，具體數值會隨口徑、窗口與數據源變化。

| 時間 | 事件 | 波動率變化 | 相關性變化 |
|-----|------|----------|----------|
| 2008.09 | 雷曼倒閉 | 15% → 80% | 0.3 → 0.95 |
| 2020.03 | COVID爆發 | 12% → 85% | 0.4 → 0.90 |
| 2022.01 | 美聯儲加息 | 15% → 30% | 0.5 → 0.70 |

**Regime Shift 對策略的影響**：
- 在舊 Regime 下訓練的模型，在新 Regime 下會失效
- 相關性突變意味着分散投資突然失效
- 波動率突變意味着止損位置需要重新計算

**這就是為什麼需要多智能體**——不同 Regime 需要不同策略，一個模型應付不來。Meta Agent 的核心任務就是識別當前 Regime，並將任務分發給對應的專家 Agent。

<details>
<summary>💻 代碼實現（工程師參考）</summary>

```python
def detect_regime_change(returns, window=60):
    """簡單的 Regime 變化檢測"""
    rolling_vol = returns.rolling(window).std()
    vol_change = rolling_vol.diff().abs()
    threshold = vol_change.quantile(0.95)
    regime_changes = vol_change > threshold
    print(f"檢測到 {regime_changes.sum()} 個潛在的 Regime 變化點")
    return regime_changes
```

</details>

## 3.5 常見誤區

**誤區一：正態分佈足夠描述市場**

不對。真實市場是厚尾分佈，極端事件發生頻率遠超正態分佈預測。LTCM 假設正態分佈，結果"百萬年一遇"的事件在幾週內發生。

**誤區二：波動率越低越安全**

不完全對。低波動可能是暴風雨前的平靜。更危險的是，低波動期往往伴隨槓桿增加，一旦波動率突然飆升，損失會被放大。

**誤區三：相關性穩定可預測**

危險的假設。正常時期相關性 0.3 的資產，危機時可能飆升到 0.9。分散投資在你最需要它的時候可能失效。

**誤區四：歷史數據能預測未來**

只能部分預測。市場存在 Regime Shift（結構性斷裂），過去的統計規律可能突然失效。2008 年、2020 年的市場與之前完全不同。

## 3.6 多智能體視角

不同 Agent 可以使用不同的統計假設：

| Agent | 統計假設 | 適用場景 |
|-------|---------|---------|
| **Trend Agent** | 動量存在（正自相關） | 趨勢市場 |
| **Mean Reversion Agent** | 均值迴歸（負自相關） | 震盪市場 |
| **Risk Agent** | 厚尾分佈 + 波動聚集 | 所有場景 |
| **Regime Agent** | 非平穩 + 結構斷裂 | 狀態識別 |

**關鍵洞察**：
- 不要讓所有 Agent 用同一套統計假設
- Risk Agent 必須用最保守的假設（厚尾、極端事件頻繁）
- Meta Agent 的職責是識別當前 Regime，分發給合適的 Agent
