## LTCM：諾貝爾獎得主的致命假設

1998 年，Long-Term Capital Management（LTCM）坐擁兩位諾貝爾經濟學獎得主、華爾街頂尖的數學家，以及 1,250 億美元資產。

他們的模型精妙絕倫，建基於一個核心假設：**市場 return 服從 normal distribution**。

按照 normal distribution，他們的策略單日虧損超過 1% 的機率是十萬分之一。一年有 252 個交易日，理論上每 400 年才會發生一次。

**然後俄羅斯債務違約了。**

1998 年 8 月 21 日，LTCM 單日虧損 5.5 億美元。其後一個月，他們虧掉 46 億美元，幾乎是全部資本。按照 normal distribution，這件事的機率是 10^-27，大約等於宇宙誕生以來每秒都不會發生一次的事。

但它發生了。

**問題出在哪裏？**

1. **市場並不服從 normal distribution**：真實市場是「fat-tailed distribution」，極端事件發生的頻率遠高於 normal distribution 的預測
2. **Correlation 會突然飆升**：平常時期 asset 之間的 correlation 很低；危機時所有 asset 的 correlation 都飆升至 1
3. **Volatility 會 cluster**：大跌之後往往跟着更多大跌，並非獨立的「擲硬幣」

LTCM 的教訓：**模型不是不夠精確，而是數學假設根本就錯了。**

本課目標：幫助你理解金融數據的真正特性，避免用「擲硬幣」的數學去分析市場。

## 3.1 Time Series 基礎

### Sequence 與 IID 假設

傳統統計學假設數據是 **IID（Independent and Identically Distributed）**：
- Independent：今天的數據與昨天無關
- Identically Distributed：每天的數據來自同一個分佈

**金融數據幾乎從不滿足 IID 假設**：

```python
import numpy as np

# IID data: coin flips
coin_flips = np.random.choice([0, 1], size=100)  # Each flip independent, probability constant

# Financial data: today's price depends on yesterday
prices = [100]
for _ in range(99):
    # Today's price = yesterday's price + random change
    prices.append(prices[-1] * (1 + np.random.normal(0, 0.02)))
```

**為何這很重要？**
- 如果你用 IID 假設建模，會低估連續虧損的機率
- 真實市場有「momentum」：升市傾向繼續升，跌市傾向繼續跌

### Lag 與 Autocorrelation

**Autocorrelation**：當前數值與過去數值之間的 correlation。

**紙上計算例子**：

假設連續 5 日的 return 為：+2%、-1%、+3%、+2%、-2%

| 今日 (t) | 昨日 (t-1) |
|-----------|-----------------|
| -1% | +2% |
| +3% | -1% |
| +2% | +3% |
| -2% | +2% |

觀察到的規律：
- 昨日升，今日有時升有時跌 -> Autocorrelation 接近 0（隨機）
- 如果昨日升通常意味着今日升 -> 正 autocorrelation（momentum）
- 如果昨日升通常意味着今日跌 -> 負 autocorrelation（mean reversion）

**SPY（S&P 500 ETF）日 return 的 autocorrelation 通常接近零**（例如 2010-2020 年約 0.02），顯示美股日 return 接近 random walk，短期難以預測。具體數值視乎樣本期及方法而有所不同。

**解讀**：
- Autocorrelation 接近 0 -> 過去對未來的預測價值低（weak-form efficient market）
- 顯著正 autocorrelation -> Momentum effect（trend following 可能有效）
- 顯著負 autocorrelation -> Mean reversion effect

<details>
<summary>代碼實現（給工程師）</summary>

```python
import pandas as pd

def calculate_autocorrelation(series, lag=1):
    """Calculate autocorrelation coefficient at lag periods"""
    return series.autocorr(lag=lag)

# Example: SPY (S&P 500 ETF) daily return autocorrelation
returns = prices_series.pct_change().dropna()

print(f"Lag-1 autocorrelation: {calculate_autocorrelation(returns, 1):.3f}")
print(f"Lag-5 autocorrelation: {calculate_autocorrelation(returns, 5):.3f}")
```

</details>

### Stationarity 檢驗

**Stationarity**：統計特性（mean、variance）不隨時間改變。

```python
from statsmodels.tsa.stattools import adfuller

def check_stationarity(series, name="Series"):
    """ADF test: Determine if series is stationary"""
    result = adfuller(series.dropna())
    print(f"{name}:")
    print(f"  ADF Statistic: {result[0]:.4f}")
    print(f"  p-value: {result[1]:.4f}")
    print(f"  Conclusion: {'Stationary' if result[1] < 0.05 else 'Non-stationary'}")

# Price series are typically non-stationary
check_stationarity(prices_series, "Price Series")

# Return series are typically stationary
check_stationarity(returns_series, "Returns Series")
```

**為何要檢驗 stationarity？**
- 大部分統計模型假設輸入是 stationary
- 對 non-stationary 序列建模會產生「spurious regression」
- **解決方法**：用 return（差分）代替價格

## 3.2 Return 的數學定義

### Simple Return 與 Log Return

**紙上計算**：

假設 AAPL 由 $100 升至 $110：

```
Simple return = (110 - 100) / 100 = 10%
Log return = ln(110/100) = ln(1.1) ~ 9.53%
```

**為何量化人員常用 log return？** 看看這個例子：

**Additivity 問題**（用計算機驗證）：

| | 第 1 日 | 第 2 日 | 總 Return |
|--|-------|-------|--------------|
| 價格 | $100 -> $110 | $110 -> $100 | $100 -> $100 |
| Simple Return | +10% | -9.09% | **0%** |
| 直接相加 | | | 10% - 9.09% = 0.91% X |
| Log Return | +9.53% | -9.53% | **0%** |
| 直接相加 | | | 9.53% - 9.53% = 0% ✓ |

**結論**：Log return 可以直接相加；simple return 必須相乘。計算 100 日累積 return 時，log return 只需 100 次加法，而 simple return 需要 100 次乘法。

| 特性 | Simple Return | Log Return |
|----------|---------------|------------|
| Additivity | X 多期 return 不能直接相加 | O 多期 return 可以直接相加 |
| 對稱性 | X 升 10% 再跌 10% != 0 | O 較對稱 |
| Normality 假設 | 較難滿足 | 較接近 normal |

### 累積 Return 計算

**紙上計算**：

連續 5 日的日 return：+1%、-2%、+3%、+1%、-1%

**Simple return 累積**（相乘）：
```
(1+0.01) x (1-0.02) x (1+0.03) x (1+0.01) x (1-0.01) - 1
= 1.01 x 0.98 x 1.03 x 1.01 x 0.99 - 1
= 1.0194 - 1 = 1.94%
```

**Log return 累積**（直接相加）：
```
0.01 + (-0.02) + 0.03 + 0.01 + (-0.01) = 2%
```

兩種方法結果相近，但 log return 計算更簡單。

### 年化 Return

**紙上計算**：

假設你在 60 個交易日內賺了 5%，年化 return 是多少？

```
Annualized Return = (1 + 5%)^(252/60) - 1
                  = 1.05^4.2 - 1
                  = 1.227 - 1
                  = 22.7%
```

**為何是 252？** 美股一年約有 252 個交易日（365 日 - 週末 - 假期）。

**常見錯誤**：
- X 直接將月 return 乘以 12 作為年化（忽略複利）
- X 用日曆日而非交易日（應該用 252，而不是 365）
- X 在扣除手續費之前就年化

<details>
<summary>代碼實現（給工程師）</summary>

```python
def cumulative_return(returns, method='simple'):
    """Calculate cumulative return"""
    if method == 'simple':
        return (1 + returns).prod() - 1  # Multiply
    else:
        return returns.sum()  # Direct sum

def annualize_return(total_return, days, trading_days_per_year=252):
    """Annualized return"""
    years = days / trading_days_per_year
    return (1 + total_return) ** (1 / years) - 1

# Example: Earned 5% over 60 days
ann_return = annualize_return(0.05, 60)
print(f"Annualized return: {ann_return:.2%}")  # ~ 22.7%
```

</details>

## 3.3 風險的數學定義

### Variance 與 Standard Deviation

**紙上計算**：

假設 5 日的日 return：+1%、-2%、+3%、0%、-1%

**第 1 步：計算 mean**
```
Mean = (1 - 2 + 3 + 0 - 1) / 5 = 0.2%
```

**第 2 步：計算 variance**（與 mean 之差的平方的平均值）
```
Variance = [(1-0.2)^2 + (-2-0.2)^2 + (3-0.2)^2 + (0-0.2)^2 + (-1-0.2)^2] / 5
         = [0.64 + 4.84 + 7.84 + 0.04 + 1.44] / 5
         = 14.8 / 5 = 2.96 (%^2)
```

**第 3 步：計算 standard deviation**（volatility）
```
Daily volatility = sqrt(2.96) ~ 1.72%
```

**第 4 步：年化**
```
Annualized volatility = Daily volatility x sqrt(252) ~ 1.72% x 15.87 ~ 27.3%
```

**Volatility 的直觀意義**：

| 年化 Volatility | 典型 Asset | 一年內可能的範圍（68% 機率） |
|----------------------|---------------|----------------------------------------|
| 15% | 大型股（SPY） | -15% 至 +15% |
| 30% | 科技股（TSLA） | -30% 至 +30% |
| 80% | 加密貨幣（BTC） | -80% 至 +80% |

**記住這條公式**：年化 volatility = 日 volatility x sqrt(252) ~ 日 volatility x 16

<details>
<summary>代碼實現（給工程師）</summary>

```python
def calculate_volatility(returns, annualize=True, trading_days=252):
    """Calculate volatility (standard deviation)"""
    daily_vol = returns.std()
    if annualize:
        return daily_vol * np.sqrt(trading_days)
    return daily_vol

# Example
daily_returns = pd.Series([0.01, -0.02, 0.03, 0, -0.01])
annual_vol = calculate_volatility(daily_returns)
print(f"Annualized volatility: {annual_vol:.2%}")
```

</details>

### Covariance 與 Correlation

**直觀理解**：

Correlation coefficient 衡量兩個 asset 是否「同步移動」：

| Correlation | 意義 | 例子 |
|-------------|---------|---------|
| +1 | 完全同步：A 升則 B 升 | 同板塊股票（AAPL vs MSFT） |
| 0 | 無關：A 的走勢與 B 無關 | 黃金 vs 科技股 |
| -1 | 完全相反：A 升則 B 跌 | 股票 vs VIX（恐慌指數） |

**實際市場的 correlation**（參考值）：

| Asset 組合 | 平常時期 Correlation | 危機時期 Correlation |
|------------|---------------------------|---------------------------|
| AAPL vs MSFT | +0.7 | +0.9 |
| SPY vs TLT（債券） | -0.3 | -0.5 或 +0.8 |
| SPY vs GLD（黃金） | +0.1 | -0.2 |

**危機期間的「correlation spike」**：平常互不相關的 asset，在危機時 correlation 可突然飆升至 0.9。這正是令 LTCM 失手的原因，他們假設 correlation 穩定。

**Multi-Agent 視角**：Portfolio Agent 的核心工作是找出低 correlation 的 asset 來建立 portfolio，但 Risk Agent 必須考慮「危機時 correlation spike」的風險。

<details>
<summary>代碼實現（給工程師）</summary>

```python
def analyze_correlation(returns_a, returns_b):
    """Analyze correlation between two assets"""
    corr = returns_a.corr(returns_b)
    print(f"Correlation coefficient: {corr:.3f}")

    if corr > 0.7:
        print("-> Highly positive correlated: Move together, poor diversification")
    elif corr < -0.3:
        print("-> Negatively correlated: Natural hedge, good for portfolio")
    else:
        print("-> Low correlation: Valuable for risk diversification")
```

</details>

### 分佈假設的危險

**Normal distribution 假設會害死你。** 這是 LTCM 的核心教訓。

**紙上計算**：

假設 SPY 年化 volatility 為 20%，日 volatility 約為 1.26%（= 20% / sqrt(252)）。

在 normal distribution 下：
- 單日跌幅 > 1 sigma（1.26%）的機率 = 16%（normal）
- 單日跌幅 > 2 sigma（2.52%）的機率 = 2.3%（每月 0.5 次）
- 單日跌幅 > 3 sigma（3.78%）的機率 = 0.13%（每 3 年一次）
- 單日跌幅 > 4 sigma（5.04%）的機率 = 0.003%（每 125 年一次）

**但實際發生了什麼？**

| 日期 | 事件 | SPY 單日跌幅 | 按 normal distribution 是「多少 sigma」 | 理論頻率 |
|------|-------|---------------------|----------------------------------------|---------------------|
| 2020-03-16 | COVID 崩盤 | -12.0% | 9.5 sigma | 10^20 年 |
| 2008-10-15 | 金融危機 | -9.0% | 7.1 sigma | 10^12 年 |
| 2011-08-08 | 美國評級被下調 | -6.7% | 5.3 sigma | 1,500 萬年 |
| 2018-02-05 | Volatility 崩盤 | -4.1% | 3.3 sigma | 4 年 |

**結論**：normal distribution 說「10^20 年一遇」的事件，實際上每隔幾年就發生一次。

**這就是「fat-tailed distribution」的威力**：極端事件發生的頻率遠高於 normal distribution 的預測。如果你的風險模型假設 normal distribution，在某次「black swan」事件中必然爆倉。

## 3.4 金融 Time Series 的特殊性質

### Fat Tails

**兩個關鍵指標**：

1. **Skewness**：分佈是否對稱？
   - Skewness = 0 -> 對稱（升跌幅度相近）
   - Skewness < 0 -> 左偏（崩盤多於急升）
   - **股市的 skewness 通常為 -0.5 至 -1**，顯示崩盤風險大於急升機會

2. **Kurtosis**：尾部有多「肥」？
   - Kurtosis = 3 -> Normal distribution
   - Kurtosis > 3 -> Fat tails（極端事件比 normal distribution 預測的多）
   - **股市的 kurtosis 通常為 5-10**，遠高於 normal distribution 的 3

| 指標 | Normal Distribution | SPY 實際 | 意義 |
|--------|---------------------|------------|---------|
| Skewness | 0 | -0.7 | 崩盤更嚴重 |
| Kurtosis | 3 | 8 | 極端事件頻繁 |

**Fat tails 對策略的影響**：
- Stop-loss 必須考慮 gap 風險（隔夜崩盤可能跳過你的止損價）
- VaR 模型會嚴重低估風險
- 需要用 Expected Shortfall（CVaR）代替 VaR

<details>
<summary>代碼實現（給工程師）</summary>

```python
def analyze_tail_risk(returns):
    """Analyze tail risk"""
    skew = returns.skew()  # Skewness
    kurt = returns.kurtosis()  # Kurtosis (excess)

    print(f"Skewness: {skew:.3f} {'(negative skew, beware of crashes)' if skew < -0.5 else ''}")
    print(f"Kurtosis: {kurt+3:.3f} {'(fat tails!)' if kurt > 0 else ''}")
```

</details>

### Volatility Clustering

**GARCH Effect**：大 volatility 之後傾向跟着大 volatility，小 volatility 之後傾向跟着小 volatility。

**直觀理解**：

回想 2020 年 3 月的 COVID 崩盤：
- 3 月 9 日：SPY 跌 7.6%
- 3 月 12 日：SPY 跌 9.5%
- 3 月 16 日：SPY 跌 12.0%

崩盤並非獨立的「擲硬幣」，一旦開始往往持續。這就是 volatility clustering。

**Volatility 的 autocorrelation 高達 0.7-0.9**，遠高於 return 的 autocorrelation（約 0）。這意味着：
- Return 幾乎無法預測（random walk）
- **Volatility 是可以預測的**（明天的 volatility 很可能與今天相近）

**實際意義**：
- Volatility 的可預測性 > Return 的可預測性
- Trend Agent 應在低 volatility 時建倉，高 volatility 時減倉
- Risk Agent 應根據近期 volatility 動態調整 stop-loss

<details>
<summary>代碼實現（給工程師）</summary>

```python
def detect_volatility_clustering(returns, window=20):
    """Detect volatility clustering"""
    rolling_vol = returns.rolling(window).std()
    vol_autocorr = rolling_vol.autocorr(lag=1)
    print(f"Volatility lag-1 autocorrelation: {vol_autocorr:.3f}")
```

</details>

### Non-Stationarity 與 Regime Shift

市場會在不同的「regime」之間切換，每個 regime 有不同的統計特性：

| Regime | 特徵 | 適合的策略 |
|--------|-----------------|-------------------|
| **Bull Market** | 低 volatility、正 return、低 correlation | Momentum、buy and hold |
| **Sideways** | 中等 volatility、return 接近 0 | Mean reversion |
| **Crisis** | 高 volatility、負 return、高 correlation | 減倉、hedge |

**典型的 structural break 案例（約數）**：

> 注意：下表顯示的是典型幅度；具體數值會因方法、window 及數據源而異。

| 時間 | 事件 | Volatility 變化 | Correlation 變化 |
|------|-------|-------------------|-------------------|
| 2008.09 | Lehman 倒閉 | 15% -> 80% | 0.3 -> 0.95 |
| 2020.03 | COVID 爆發 | 12% -> 85% | 0.4 -> 0.90 |
| 2022.01 | Fed 加息 | 15% -> 30% | 0.5 -> 0.70 |

**Regime Shift 對策略的影響**：
- 用舊 regime 訓練的模型，在新 regime 中會失效
- Correlation spike 意味着分散投資突然失效
- Volatility spike 意味着 stop-loss 位置需要重新計算

**這就是需要 multi-agent 的原因**：不同 regime 需要不同策略，一個模型應付不了所有情況。Meta Agent 的核心任務是識別當前 regime，並派發給合適的專職 Agent。

<details>
<summary>代碼實現（給工程師）</summary>

```python
def detect_regime_change(returns, window=60):
    """Simple regime change detection"""
    rolling_vol = returns.rolling(window).std()
    vol_change = rolling_vol.diff().abs()
    threshold = vol_change.quantile(0.95)
    regime_changes = vol_change > threshold
    print(f"Detected {regime_changes.sum()} potential regime change points")
    return regime_changes
```

</details>

## 3.5 常見誤區

**誤區 1：Normal distribution 足以描述市場**

錯。真實市場是 fat-tailed distribution，極端事件發生的頻率遠高於 normal distribution 的預測。LTCM 假設 normal distribution，結果「百萬年一遇」的事件在幾星期內就發生了。

**誤區 2：Volatility 越低越安全**

不盡然。低 volatility 可能是暴風雨前的寧靜。更危險的是，低 volatility 時期往往伴隨着 leverage 增加；一旦 volatility 突然飆升，虧損會被放大。

**誤區 3：Correlation 穩定且可預測**

這是危險的假設。平常 correlation 為 0.3 的 asset，在危機時可飆升至 0.9。分散投資可能正好在你最需要它的時候失效。

**誤區 4：歷史數據可以預測未來**

只是部分可以。市場會經歷 Regime Shift（structural break），過去的統計規律可能突然失效。2008 年和 2020 年的市場與之前完全不同。

## 3.6 Multi-Agent 視角

不同的 Agent 可以使用不同的統計假設：

| Agent | 統計假設 | 適用情境 |
|-------|----------------------|---------------------|
| **Trend Agent** | Momentum 存在（正 autocorrelation） | 趨勢市 |
| **Mean Reversion Agent** | Mean reversion（負 autocorrelation） | 橫行市 |
| **Risk Agent** | Fat-tailed distribution + volatility clustering | 所有情境 |
| **Regime Agent** | Non-stationary + structural break | Regime 識別 |

**關鍵洞察**：
- 不要讓所有 Agent 使用相同的統計假設
- Risk Agent 必須使用最保守的假設（fat tails、極端事件頻繁）
- Meta Agent 的職責是識別當前 regime，並派發給合適的 Agent
