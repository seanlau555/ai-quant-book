# 背景知識：交易所與訂單簿機制

> 理解交易所如何運作，是理解滑點、執行和市場微觀結構的基礎。

---

## 一、交易所類型

### 1.1 中心化交易所 (CEX)

**代表**：NYSE、NASDAQ、上交所、Binance

**特點**：
- 統一撮合引擎
- 中央訂單簿
- 高流動性
- 受監管

### 1.2 去中心化交易所 (DEX)

**代表**：Uniswap、dYdX

**特點**：
- 智能合約撮合
- AMM 或訂單簿
- 無需信任中介
- 延遲較高

---

## 二、訂單簿 (Order Book)

### 2.1 基本結構

```
賣方（Ask）           價格          買方（Bid）
                    $101.50
50 股              $101.25
100 股             $101.00
                   $100.75         200 股
                   $100.50         150 股
                   $100.25         80 股
```

- **Bid（買盤）**：買方願意支付的最高價
- **Ask（賣盤）**：賣方願意接受的最低價
- **Spread（價差）**：Best Ask - Best Bid

### 2.2 訂單簿深度

**Level 1**：只有最優買賣價
```
Best Bid: $100.75 × 200
Best Ask: $101.00 × 100
```

**Level 2**：多檔報價
```
Bid:
  $100.75 × 200
  $100.50 × 150
  $100.25 × 80

Ask:
  $101.00 × 100
  $101.25 × 50
  $101.50 × 30
```

**Level 3**：每筆訂單詳情（通常不公開）

## 三、訂單類型

### 3.1 市價單 (Market Order)

**定義**：以當前最優價格立即成交

**優點**：保證成交
**缺點**：不保證價格，可能產生滑點

**示例**：
```
訂單簿：
  Ask: $101.00 × 100, $101.25 × 50

市價買入 120 股：
  100 股 @ $101.00
  20 股 @ $101.25

平均成交價 = (100×101.00 + 20×101.25) / 120 = $101.04
滑點 = $101.04 - $101.00 = $0.04
```

### 3.2 限價單 (Limit Order)

**定義**：只在指定價格或更優價格成交

**優點**：價格確定
**缺點**：可能不成交

**示例**：
```
限價買入 100 股 @ $100.75

如果當前 Best Ask = $101.00：
  → 訂單進入買盤排隊
  → 等待賣方願意以 $100.75 賣出
```

### 3.3 其他訂單類型

| 類型 | 說明 | 用途 |
|-----|------|-----|
| 止損單 (Stop) | 觸發價格後變為市價單 | 止損 |
| 止損限價單 | 觸發後變為限價單 | 精確止損 |
| 冰山單 | 只顯示部分數量 | 隱藏大單 |
| IOC | 立即成交或取消 | 避免掛單 |
| FOK | 全部成交或取消 | 大單執行 |
| GTC | 一直有效直到取消 | 長期掛單 |

## 四、撮合機制

### 4.1 價格優先、時間優先

**規則**：
1. 價格更優的訂單先成交
2. 同價格時，先到的訂單先成交

**示例**：
```
買盤排隊：
  1. 09:00:01 買入 $100.75
  2. 09:00:05 買入 $100.75
  3. 09:00:03 買入 $100.50

賣方市價賣出 → 先成交 #1，再成交 #2
```

### 4.2 連續撮合 vs 集合競價

**連續撮合**：
- 訂單實時匹配
- 適用於正常交易時段

**集合競價 (Call Auction)**：
- 收集一段時間的訂單，統一確定開盤/收盤價。
- **A股開盤集合競價 (9:15-9:25)**：
    - **9:15-9:20**：可以報單，也可以撤單。（常有虛假報單探測壓力）
    - **9:20-9:25**：可以報單，**不再允許撤單**。（真實意圖展現）
- 減少價格操縱，增加開盤流動性。

## 五、做市商 (Market Maker)

### 5.1 角色

- 持續提供買賣報價
- 提供流動性
- 賺取 Bid-Ask Spread

### 5.2 做市商策略

```
做市商報價：
  Bid: $100.00 × 1000
  Ask: $100.10 × 1000

Spread = $0.10

如果買賣訂單平衡：
  買入 1000 股 @ $100.00
  賣出 1000 股 @ $100.10
  利潤 = 1000 × $0.10 = $100
```

### 5.3 風險

- **存貨風險**：持有過多單邊頭寸
- **逆向選擇**：被知情交易者"狙擊"

## 六、市場微觀結構

### 6.1 價差的決定因素

| 因素 | 影響 |
|-----|------|
| 流動性 | 流動性高 → 價差小 |
| 波動率 | 波動大 → 價差大 |
| 信息不對稱 | 信息不對稱高 → 價差大 |
| 交易量 | 交易量大 → 價差小 |

### 6.2 市場衝擊

**定義**：大單對價格的影響

**臨時衝擊**：訂單執行時的價格偏移，之後恢復
**永久衝擊**：訂單攜帶信息，價格永久改變

**估算公式**（簡化）：
```
市場衝擊 ≈ σ × √(Q / ADV)

σ = 日波動率
Q = 訂單量
ADV = 平均日成交量
```

### 6.3 流動性度量

| 指標 | 公式 | 含義 |
|-----|------|-----|
| Bid-Ask Spread | Ask - Bid | 交易成本 |
| Depth | 訂單簿深度 | 可容納訂單量 |
| Resilience | 價格恢復速度 | 衝擊後恢復能力 |
| Turnover | 日成交量 / 總股本 | 活躍度 |

## 七、高頻交易 (HFT)

### 7.1 特點

- 持倉時間極短（毫秒級）
- 大量訂單（每秒數千筆）
- 低延遲（微秒級）
- 高勝率、低單筆利潤

### 7.2 常見策略

| 策略 | 說明 |
|-----|------|
| 做市 | 提供流動性賺 Spread |
| 套利 | 跨市場價差套利 |
| 動量 | 探測大單跟隨 |
| 統計套利 | 高頻均值迴歸 |

### 7.3 技術要求

- 低延遲網絡（Co-location）
- FPGA / ASIC 硬件
- 納秒級時鐘同步
- 專用交易所接口

---

## 八、延遲的重要性

### 8.1 延遲來源

| 來源 | 典型延遲 |
|-----|---------|
| 網絡傳輸 (光纖) | 1-50 ms (跨城) |
| 交易所處理 (撮合) | 10-100 μs (微秒) |
| 本地處理 (決策) | 1-10 μs (微秒) |
| FPGA 硬線加速 | 100-500 ns (納秒) |

### 8.2 延遲對策略的影響

```
策略類型          可接受延遲
核心 HFT 做市       < 10 μs (微秒)
跨市場套利         < 5 ms (物理極限)
日內量化趨勢       < 10-100 ms
日頻/波段策略      < 1 秒
```

## 九、實踐建議

### 9.1 對於非高頻策略

1. **關注流動性**：選擇流動性好的標的
2. **分批執行**：大單拆分為小單
3. **限價優先**：避免市價單的滑點
4. **避開波動時段**：開盤/收盤流動性差

### 9.2 滑點控制

```python
# 簡單滑點估算
def estimate_slippage(order_size, avg_daily_volume, volatility):
    """
    order_size: 訂單量（股）
    avg_daily_volume: 平均日成交量
    volatility: 日波動率
    """
    participation_rate = order_size / avg_daily_volume
    slippage = volatility * (participation_rate ** 0.5)
    return slippage
```

## 十、不同市場的特點

| 市場 | 交易時間 | 特點 |
|-----|---------|-----|
| 美股 | 9:30-16:00 ET | T+1 結算(2024新規)、可日內交易、Dark Pools |
| A股 | 9:30-11:30, 13:00-15:00 | T+1 交易（當日買入次日才能賣）、漲跌停 |
| 港股 | 9:30-12:00, 13:00-16:00 | T+2、VCM冷靜期、收市競價 |
| 加密貨幣 | 24/7 | 24/7不休市、AMM與訂單簿並存 |

> **T+1 區別**：美股 T+1 指**結算**（資金交割），但當日可自由買賣；A股 T+1 指**交易限制**，當日買入的股票次日才能賣出。
