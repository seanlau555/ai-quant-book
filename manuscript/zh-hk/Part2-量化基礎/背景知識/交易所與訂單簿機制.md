# 背景知識：交易所與 Order Book 機制

> 了解交易所如何運作，是理解 slippage、execution 與 market microstructure 的基礎。

---

## 1. 交易所類型

### 1.1 中心化交易所（CEX）

**例子**：NYSE、NASDAQ、上海證券交易所、Binance

**特點**：
- 統一的 matching engine
- 中央 order book
- 高 liquidity
- 受監管

### 1.2 去中心化交易所（DEX）

**例子**：Uniswap、dYdX

**特點**：
- 以 smart contract 進行撮合
- AMM 或 order book
- 無需可信任的中介
- 較高 latency

---

## 2. Order Book

### 2.1 基本結構

```
Sell Side (Ask)        Price          Buy Side (Bid)
                      $101.50
50 shares             $101.25
100 shares            $101.00
                      $100.75         200 shares
                      $100.50         150 shares
                      $100.25         80 shares
```

- **Bid**：買家願意支付的最高價
- **Ask**：賣家願意接受的最低價
- **Spread**：Best Ask - Best Bid

### 2.2 Order Book 深度

**Level 1**：只有 best bid/ask
```
Best Bid: $100.75 × 200
Best Ask: $101.00 × 100
```

**Level 2**：多個價位
```
Bid:
  $100.75 × 200
  $100.50 × 150
  $100.25 × 80

Ask:
  $101.00 × 100
  $101.25 × 50
  $101.50 × 30
```

**Level 3**：個別訂單詳情（通常不公開）

## 3. 訂單類型

### 3.1 Market Order

**定義**：以當前最佳價格即時成交

**優點**：保證成交
**缺點**：價格無保證，可能產生 slippage

**例子**：
```
Order Book:
  Ask: $101.00 × 100, $101.25 × 50

Market buy 120 shares:
  100 shares @ $101.00
  20 shares @ $101.25

Average execution price = (100×101.00 + 20×101.25) / 120 = $101.04
Slippage = $101.04 - $101.00 = $0.04
```

### 3.2 Limit Order

**定義**：只會以指定價格或更佳價格成交

**優點**：價格確定
**缺點**：未必成交

**例子**：
```
Limit buy 100 shares @ $100.75

If current Best Ask = $101.00:
  → Order enters bid queue
  → Wait for seller willing to sell at $100.75
```

### 3.3 其他訂單類型

| 類型 | 說明 | 使用場景 |
|------|-------------|----------|
| Stop Order | 觸及觸發價時變為 market order | Stop loss |
| Stop-Limit | 觸發後變為 limit order | 精確的 stop loss |
| Iceberg | 只顯示部分數量 | 隱藏大額訂單 |
| IOC | Immediate or Cancel | 避免訂單掛單等候 |
| FOK | Fill or Kill | 大額訂單執行 |
| GTC | Good Till Cancelled | 長期掛單 |

## 4. 撮合機制

### 4.1 價格優先、時間優先

**規則**：
1. 價格較佳的訂單先成交
2. 價格相同時，較早的訂單先成交

**例子**：
```
Bid queue:
  1. 09:00:01 bid @ $100.75
  2. 09:00:05 bid @ $100.75
  3. 09:00:03 bid @ $100.50

Seller market sells → First #1 executes, then #2
```

### 4.2 連續撮合 vs 集合競價

**連續撮合（Continuous Matching）**：
- 訂單即時撮合
- 用於正常交易時段

**集合競價（Call Auction）**：
- 在一段時間內收集訂單，然後統一決定開市/收市價
- **A 股開市集合競價（9:15-9:25）**：
    - **9:15-9:20**：可以落單及撤單（常有虛假訂單用作試探壓力）
    - **9:20-9:25**：可以落單，**不能撤單**（真實意圖浮現）
- 減少價格操縱，增加開市 liquidity

## 5. Market Maker

### 5.1 角色

- 持續提供 bid 及 ask 報價
- 提供 liquidity
- 賺取 Bid-Ask Spread

### 5.2 Market Making 策略

```
Market maker quotes:
  Bid: $100.00 × 1000
  Ask: $100.10 × 1000

Spread = $0.10

If buy and sell orders are balanced:
  Buy 1000 shares @ $100.00
  Sell 1000 shares @ $100.10
  Profit = 1000 × $0.10 = $100
```

### 5.3 風險

- **Inventory risk**：持有過多單邊倉位
- **Adverse selection**：被 informed trader「狙擊」（picked off）

## 6. Market Microstructure

### 6.1 Spread 的決定因素

| 因素 | 影響 |
|--------|--------|
| Liquidity | Liquidity 高 → Spread 小 |
| Volatility | Volatility 高 → Spread 大 |
| Information asymmetry | Asymmetry 高 → Spread 大 |
| Volume | Volume 高 → Spread 小 |

### 6.2 Market Impact

**定義**：大額訂單對價格的影響

**Temporary impact**：執行期間的價格偏移，事後會回復
**Permanent impact**：訂單帶有資訊，價格出現永久改變

**估算公式**（簡化）：
```
Market Impact ≈ σ × √(Q / ADV)

σ = Daily volatility
Q = Order quantity
ADV = Average daily volume
```

### 6.3 Liquidity 度量

| 指標 | 公式 | 意義 |
|--------|---------|---------|
| Bid-Ask Spread | Ask - Bid | 交易成本 |
| Depth | Order book depth | 訂單承載能力 |
| Resilience | Price recovery speed | Impact 後的回復 |
| Turnover | Daily volume / Float | 活躍程度 |

## 7. 高頻交易（HFT）

### 7.1 特點

- 持倉時間極短（毫秒級）
- 訂單數量龐大（每秒數千張）
- 低 latency（微秒級）
- 高勝率，每筆交易利潤低

### 7.2 常見策略

| 策略 | 說明 |
|----------|-------------|
| Market Making | 提供 liquidity，賺取 spread |
| Arbitrage | 跨市場價差 |
| Momentum | 偵測並跟隨大額訂單 |
| Statistical Arbitrage | 高頻 mean reversion |

### 7.3 技術要求

- 低 latency 網絡（Co-location）
- FPGA / ASIC 硬件
- 納秒級時鐘同步
- 專用交易所接口

---

## 8. Latency 的重要性

### 8.1 Latency 來源

| 來源 | 典型 Latency |
|--------|-----------------|
| 網絡傳輸（光纖） | 1-50 ms（跨城市） |
| 交易所處理（matching） | 10-100 μs（微秒） |
| 本地處理（decision） | 1-10 μs（微秒） |
| FPGA 硬件加速 | 100-500 ns（納秒） |

### 8.2 Latency 對策略的影響

```
Strategy Type           Acceptable Latency
Core HFT Market Making    < 10 μs (microseconds)
Cross-market Arbitrage    < 5 ms (physical limit)
Intraday Quant Trend      < 10-100 ms
Daily/Swing Strategies    < 1 second
```

## 9. 實用建議

### 9.1 非 HFT 策略

1. **注重 liquidity**：選擇 liquidity 充足的標的
2. **拆單執行**：把大額訂單拆成較細的訂單
3. **優先使用 limit order**：避免 market order 的 slippage
4. **避開波動時段**：開市/收市時 liquidity 較差

### 9.2 Slippage 控制

```python
# Simple slippage estimation
def estimate_slippage(order_size, avg_daily_volume, volatility):
    """
    order_size: Order quantity (shares)
    avg_daily_volume: Average daily volume
    volatility: Daily volatility
    """
    participation_rate = order_size / avg_daily_volume
    slippage = volatility * (participation_rate ** 0.5)
    return slippage
```

## 10. 不同市場的特點

| 市場 | 交易時間 | 特點 |
|--------|---------------|-----------------|
| 美股 | 9:30-16:00 ET | T+1 settlement（2024 年規則）、可 day trade、Dark Pools |
| A 股 | 9:30-11:30、13:00-15:00 | T+1 交易（今日買入，明日才可賣出）、價格限制（price limit） |
| 港股 | 9:30-12:00、13:00-16:00 | T+2 settlement、VCM 冷靜期、收市競價 |
| Crypto | 24/7 | 永不休市，AMM 與 order book 並存 |

> **T+1 Settlement vs T+1 交易**：這是兩個本質上不同的概念。美國 T+1 settlement（2024 年 5 月起生效）指資金與股份交收於下一個營業日完成，但你可以在同一個交易日內自由多次買賣同一隻股票（day trading）。中國 A 股的 T+1 交易則是一項交易限制：今日買入的股份只能在下一個交易日賣出，以防止即日來回交易。

---

> **核心原則**：理解 order book 與撮合機制，是理解為何 backtest 結果與實盤表現不同的關鍵。你的訂單並非在真空中成交，而是在複雜的市場生態中與其他訂單競爭。
