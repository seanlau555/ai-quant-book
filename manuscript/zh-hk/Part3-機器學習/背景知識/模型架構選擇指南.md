# 背景知識：Deep Learning 模型架構選擇指南

> 選對架構已成功一半。不同模型適合不同場景——沒有「萬能模型」。

---

## 1. 模型架構速查表

| 模型類型 | 參數規模 | 訓練時間 | Inference 延遲 | 適用場景 | 優點 | 缺點 |
|------------|----------------|---------------|-------------------|-----------|------------|---------------|
| **LSTM** | 1-10M | 中 | <10ms | 短期價格預測、HFT | 捕捉時間依賴，訓練穩定 | 長序列表現下降 |
| **GRU** | 0.5-5M | 較快 | <8ms | 資源有限、real-time inference | 參數較少，訓練較快 | 表達能力略遜於 LSTM |
| **Transformer** | 10-100M | 高 | 10-50ms | 多資產組合、長期趨勢 | 可並行訓練，長距離依賴 | 數據需求高，overfitting 風險 |
| **CNN** | 0.5-5M | 快 | <5ms | 技術形態識別、pattern matching | 局部特徵提取，高效 | 時間建模能力弱 |
| **CNN-LSTM Hybrid** | 5-20M | 中高 | 10-30ms | 多時間框架分析 | 結合局部與全局特徵 | 複雜度高，難以調參 |

## 2. LSTM/GRU：時間序列建模的主力

### 2.1 架構原理

LSTM（Long Short-Term Memory）透過**三個 gating mechanism** 控制資訊流：

```
Input Gate:  Decides what new information to write to memory
Forget Gate: Decides what old information to discard
Output Gate: Decides what memory information to output
```

**GRU（Gated Recurrent Unit）** 是 LSTM 的簡化版本：
- 將 input gate 與 forget gate 合併成單一「update gate」
- 參數量減少約 25%，訓練更快
- 在小數據集上表現與 LSTM 相若

### 2.2 典型架構配置

```
Single-asset daily strategy:
├── Input layer: 20-60 timesteps x 10-30 features
├── LSTM layer 1: 128 units + Dropout(0.2)
├── LSTM layer 2: 64 units + Dropout(0.2)
├── Dense layer: 32 units + ReLU
└── Output layer: 1 unit (regression) or 3 units (classification: up/down/flat)

High-frequency trading (minute-level):
├── Input layer: 60-120 timesteps x 50-100 features
├── GRU layer: 256 units (speed priority)
├── Dense layer: 64 units
└── Output layer: Discrete actions (buy/sell/hold)
```

### 2.3 何時選擇 LSTM/GRU？

| 場景 | 建議 | 理由 |
|----------|----------------|-----------|
| 數據量 < 100K 樣本 | LSTM/GRU | Transformer 在小數據集上容易 overfit |
| 序列長度 < 100 步 | LSTM/GRU | LSTM 已足夠；Transformer 的優勢極小 |
| Inference 延遲 < 10ms | GRU | 參數較少，inference 較快 |
| 單一資產策略 | LSTM | 捕捉個別資產的時間模式 |

### 2.4 重要發現

根據 arXiv 論文 "Vanilla LSTMs Outperform Transformer-based Forecasting"：

> 在金融時間序列預測任務中，於**數據有限**或**序列較短**的場景下，標準 LSTM 往往勝過更複雜的 Transformer 架構。

**原因**：金融數據的 signal-to-noise ratio 低；複雜模型傾向學習噪音，而非真正的規律。

## 3. Transformer：長序列與多資產的選擇

### 3.1 核心創新

**Self-Attention Mechanism**：
- 同時關注序列中所有位置
- 捕捉長距離依賴
- 支援並行運算，訓練高效

**Positional Encoding**：
- 保留時間順序資訊
- 彌補 attention mechanism 本身不感知位置的缺陷

### 3.2 金融領域的變體

| 變體 | 改進 | 適用場景 |
|---------|-------------|-----------|
| **Informer** | Sparse attention，降低運算複雜度 | 長序列預測（>1000 步） |
| **Autoformer** | Autocorrelation mechanism 捕捉週期性 | 高度季節性的數據 |
| **StockFormer** | End-to-end reinforcement learning | 直接輸出交易決策 |
| **Higher-Order Transformer** | 高階 attention，feature interactions | 股價預測（準確度 +5-10%） |

### 3.3 何時選擇 Transformer？

| 場景 | 建議 | 理由 |
|----------|----------------|-----------|
| 多資產組合（>50 隻資產） | Transformer | 同時建模資產之間的關係 |
| 長序列（>200 步） | Transformer | 長期依賴建模能力強 |
| 數據量 > 1M 樣本 | Transformer | 充分利用模型容量 |
| 宏觀經濟預測 | Transformer | 捕捉長期趨勢 |

### 3.4 注意事項

```
Transformer Pitfalls:
1. High overfitting risk → Requires strong regularization (Dropout >= 0.3)
2. High data requirements → Underperforms LSTM with insufficient samples
3. High computational cost → GPU training is essential
4. Positional encoding sensitivity → Requires adjustment for financial data
```

## 4. CNN：形態識別的強項

### 4.1 應用方式

**1D CNN**：直接處理價格序列
```
Input: Past 60 days of OHLCV data (60x5 matrix)
Kernels: Multiple sizes (3, 5, 7 days) extract features at different periods
Pooling: Max pooling or average pooling
Output: Feature vector → Classification/regression head
```

**2D CNN**：處理 K 線圖圖像
```
Input: Candlestick chart rendered as image (e.g., 224x224x3)
Architecture: Similar to ResNet or VGG
Purpose: Identifies head-and-shoulders, double bottoms, triangles, and other classic patterns
```

### 4.2 何時選擇 CNN？

| 場景 | 建議 | 理由 |
|----------|----------------|-----------|
| 技術形態識別 | CNN | 擅長提取局部空間特徵 |
| 超低延遲需求 | CNN | Inference 速度最快 |
| 相關矩陣分析 | 2D CNN | 將多資產關係視覺化 |

### 4.3 限制

```
CNN Issues in Finance:
1. Ignores temporal order → Needs positional encoding or RNN combination
2. Local receptive field → Difficulty capturing long-term dependencies
3. Candlestick chart subjectivity → Different rendering methods affect results
```

## 5. 混合架構：取長補短

### 5.1 CNN-LSTM

```
Architecture:
Input → CNN (extract local features) → LSTM (model temporal dependencies) → Output

Advantages:
- CNN quickly filters key features
- LSTM captures temporal evolution patterns
- Multi-timeframe fusion

Disadvantages:
- High tuning complexity
- Increased overfitting risk
```

### 5.2 LSTM-Transformer

```
Architecture:
Input → LSTM (local temporal) → Transformer (global context) → Output

Use Cases:
- Markets with both short-term momentum and long-term trends
- Strategies requiring regime switch detection
```

### 5.3 混合架構建議

| 數據特性 | 建議架構 |
|---------------------|-------------------------|
| 短期依賴強 + 長期依賴弱 | 以 LSTM 為主 |
| 短期依賴弱 + 長期依賴強 | 以 Transformer 為主 |
| 兩者同樣重要 | CNN-LSTM 或 LSTM-Transformer |
| 不確定 | 先用 LSTM，逐步增加複雜度 |

## 6. Reinforcement Learning 算法選擇

### 6.1 核心算法比較

| 算法 | 年化回報 | Sharpe Ratio | Max Drawdown | Sample Efficiency | 訓練穩定性 | 適用場景 |
|-----------|--------------|--------------|--------------|-------------------|-------------------|-----------|
| **DQN** | 8-15% | 0.6-1.2 | 15-25% | 中 | 中（容易發散） | HFT、discrete actions |
| **PPO** | 15-25% | 1.2-1.8 | 10-18% | 較高 | 高（收斂穩定） | 中／低頻、continuous actions |
| **A3C** | 10-18% | 0.8-1.4 | 12-22% | 較高 | 低（明顯震盪） | 並行探索、資源有限 |
| **SAC** | 12-20% | 1.0-1.6 | 12-20% | 較高 | 中高 | HFT、鼓勵探索 |
| **DDPG** | 8-15% | 0.6-1.2 | 15-25% | 中 | 低 | Continuous actions、精確倉位 |

### 6.2 選擇建議

```
Start with PPO → Best balance between stability and performance

If you need discrete actions (buy/sell/hold) → DQN
If you need continuous actions (position sizing) → PPO or SAC
If you want maximum exploration → SAC
If you have resources for parallelization → A3C
```

## 7. 實戰選型流程

### 7.1 決策樹

```
                    Data volume > 1M?
                    /            \
                  Yes             No
                   |               |
             Sequence >200?    Sequence <100?
             /        \         /        \
           Yes        No       Yes        No
            |          |        |          |
      Transformer   Hybrid   LSTM      GRU/LSTM
```

### 7.2 快速選型表

| 你的情況 | 建議架構 | 理由 |
|----------------|-------------------------|-----------|
| 初學者，想快速驗證 | **LSTM + PPO** | 成熟、穩定、教學資源豐富 |
| 日線單一資產策略 | **LSTM** | 簡單有效 |
| 分鐘級 HFT 策略 | **GRU + DQN** | 低延遲 |
| 多資產組合優化 | **Transformer** | 捕捉資產之間的關係 |
| 技術形態識別 | **CNN** | 擅長局部形態 |
| 不確定，求穩定 | **LSTM → 逐步增加複雜度** | 避免過早優化 |

## 8. 常見迷思

**迷思 1：Transformer 一定比 LSTM 好**

不對。在金融領域，數據有限且 signal-to-noise ratio 低，LSTM 往往更穩健。

**迷思 2：模型越複雜越好**

事實剛好相反。金融數據噪音大，複雜模型容易 overfit。**簡單模型 + 好 feature > 複雜模型 + 差 feature**。

**迷思 3：直接照搬 NLP/CV 的架構配置**

金融數據有獨特特性：non-stationarity、低 signal-to-noise ratio、regime changes。必須作針對性調整。

**迷思 4：只憑 backtest 指標選擇模型**

還必須考慮：inference 延遲、部署複雜度、可解釋性要求。在實盤交易中，GRU 可能比 Transformer 更實用。

## 9. 技術選型總結

| 複雜度 | 數據關係 | 建議架構 |
|------------|-------------------|-------------------------|
| 簡單線性 | 傳統 factors | LightGBM/XGBoost |
| 中等複雜 | 短期時間序列 | LSTM/GRU |
| 高度非線性 | 長期依賴 | Transformer |
| 動態決策 | 序列決策 | Reinforcement Learning (PPO) |
| 多模態數據 | 文字 + 數值 | LLM + LSTM 混合 |

### 通用訓練策略建議

1. **Experience Replay**：打破時間相關性，穩定訓練
2. **Target Network**：延遲更新以減少震盪
3. **Gradient Clipping**：防止 gradient explosion
4. **Model Ensembling**：降低單點失效風險
5. **嚴格的歷史驗證**：Walk-Forward 測試必不可少
