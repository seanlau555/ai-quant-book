# 背景知識：Feature Engineering 常見陷阱

> 量化交易中 80% 的 Alpha 來自 feature engineering，但 80% 的失敗也來自 feature engineering。

---

## 陷阱 1：未來資訊洩漏

**問題**：在計算 feature 時，不小心用上了未來數據。

```python
# Wrong Example: Using today's close for indicator, but deciding at open
df['ma20'] = df['close'].rolling(20).mean()  # Includes today's close
signal = df['close'] > df['ma20']  # Uses today's close to judge

# Correct Approach: shift(1) ensures only historical data is used
df['ma20'] = df['close'].rolling(20).mean().shift(1)
signal = df['close'] > df['ma20']
```

**偵測方法**：
- Feature 與 label 的相關性 > 0.9 -> 很可能有洩漏
- 模型準確率 > 90% -> 幾乎肯定有洩漏

---

## 陷阱 2：全域標準化

**問題**：使用整個數據集的統計量做標準化，會洩漏未來的分佈資訊。

```python
# Wrong Example
mean = df['close'].mean()  # Includes future data
std = df['close'].std()
df['normalized'] = (df['close'] - mean) / std

# Correct Approach: Rolling window normalization
df['normalized'] = (
    (df['close'] - df['close'].rolling(20).mean()) /
    df['close'].rolling(20).std()
)
```

## 陷阱 3：高度相關的 feature 冗餘

**問題**：多個 feature 之間高度相關，造成資訊冗餘和 overfitting 風險。

| Feature 組合 | 相關性 | 問題 |
|---------------|-------------|---------|
| MA5, MA10, MA20 | 0.95+ | 資訊幾乎相同 |
| RSI, Stochastic | 0.8+ | 兩者都在衡量超買／超賣 |
| Close, VWAP | 0.99 | 幾乎相同 |

**解決方法**：
- 相關性 > 0.7 時只保留一個 feature
- 使用 PCA 降維
- 揀選解釋力最強的代表

---

## 陷阱 4：對噪音 overfitting

**問題**：feature 愈多，愈有機會記住訓練數據中的噪音。

```
Feature count vs Sample count rule of thumb:

Samples / Features > 20  -> Safe zone
Samples / Features = 10  -> Warning zone
Samples / Features < 5   -> Danger zone

Example: 1000 samples, use at most 50 features
```

**解決方法**：
- 遞歸式 feature 剔除，觀察 validation set 表現
- 使用 L1 regularization 自動篩選
- 領域知識的優先度高於統計顯著性

---

## 陷阱 5：類別 feature 編碼錯誤

**問題**：錯誤處理類別 feature，會導致資訊流失或產生虛假關係。

```python
# Wrong Example: Direct numeric encoding (implies ordering)
sector_map = {'Technology': 1, 'Healthcare': 2, 'Finance': 3}
df['sector'] = df['sector_name'].map(sector_map)  # Model thinks 3 > 2 > 1

# Correct Approach: One-Hot encoding
df = pd.get_dummies(df, columns=['sector_name'])
```

---

## 陷阱 6：忽略隨時間變化的相關性

**問題**：feature 的預測力在不同時期並不穩定。

| 時期 | Momentum 因子 IC | Value 因子 IC |
|--------|-------------------|-----------------|
| 2015-2017 | 0.05 | 0.02 |
| 2018-2019 | 0.01 | 0.04 |
| 2020-2021 | 0.06 | -0.02 |

**解決方法**：
- 使用 rolling IC，而不是單一 IC
- IC 穩定性（IC/std(IC)）比 IC 絕對值更重要
- 考慮以 regime 作條件，判斷 feature 的有效性

---

## 陷阱 7：Data Snooping

**問題**：不斷重複測試，直至找到「有效」的 feature，實質上是 overfitting。

```
Test 100 features
-> Expect 5 to be "significant" at p<0.05
-> These 5 may just be random noise
```

**解決方法**：
- 使用 Bonferroni correction：p-value 門檻 = 0.05 / 測試次數
- 預留獨立的 OOS 數據集
- 記錄所有測試過的 feature，而不只是「成功」的那些

---

## 陷阱 8：忽略交易成本的影響

**問題**：高 turnover 的 feature 在實盤中會被成本蠶食。

```
Feature A: IC = 0.05, turnover 200%/month
Feature B: IC = 0.03, turnover 50%/month

Assuming one-way cost 0.2%:
Feature A cost: 200% x 0.2% x 2 = 0.8%/month
Feature B cost: 50% x 0.2% x 2 = 0.2%/month

After costs, Feature B may be better
```

## Feature Engineering 檢查清單

| 檢查項目 | 合格標準 |
|------------|------------------|
| 沒有未來資訊 | 所有 feature 都使用 shift(1) 或更早的數據 |
| Rolling 標準化 | 沒有使用全域 mean/std |
| 低相關性 | Feature 之間相關性 < 0.7 |
| 樣本比例 | Samples / Features > 20 |
| IC 穩定性 | IC / std(IC) > 0.5 |
| 成本可行性 | 扣除 turnover 成本後仍有正回報 |
