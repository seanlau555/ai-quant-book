# 背景知識：量化開源框架對比

> 揀啱 framework 可以慳返數個月開發時間。本文比較主流量化開源框架的優缺點與適用場景。

---

## 1. Framework 分類

| 類別 | Framework | 主要用途 |
|----------|-----------|--------------|
| **Backtesting Framework** | Backtrader, VectorBT, Zipline | 策略 backtest |
| **Research Framework** | QuantLib, PyAlgoTrade | Pricing、研究 |
| **RL Framework** | FinRL, TensorTrade | Reinforcement learning 交易 |
| **Full-Stack Framework** | QuantConnect, Freqtrade | Backtest + 實盤交易 |

---

## 2. Backtesting Framework 詳解

### 2.1 VectorBT

**定位**：高性能 vectorized backtesting framework

**優點**：
- Backtest 速度極快（vectorized computation）
- 內置豐富的分析指標
- 支援參數優化
- Visualization 強大
- 支援 multi-asset portfolio

**缺點**：
- 學習曲線陡峭
- 不支援 event-driven
- 難以表達複雜策略
- 沒有內置實盤交易介面

**適用場景**：參數優化、快速 backtest、策略研究

**範例代碼**：
```python
import vectorbt as vbt

# Get data
price = vbt.YFData.download('BTC-USD').get('Close')

# Dual moving average strategy
fast_ma = vbt.MA.run(price, 10)
slow_ma = vbt.MA.run(price, 30)

entries = fast_ma.ma_crossed_above(slow_ma)
exits = fast_ma.ma_crossed_below(slow_ma)

# Backtest
pf = vbt.Portfolio.from_signals(price, entries, exits)
print(pf.stats())
```

### 2.2 Backtrader

**定位**：Event-driven backtesting framework

**優點**：
- Event-driven 架構，邏輯清晰
- 支援多數據源、多 timeframe
- 內置常用 indicator
- 社群活躍
- 支援實盤交易（需要 broker adapter）

**缺點**：
- Backtest 速度較慢
- 代碼冗長
- 維護不太活躍（原作者很少更新）

**適用場景**：複雜策略、multi-asset、需要精細控制

**範例代碼**：
```python
import backtrader as bt

class SmaCross(bt.Strategy):
    params = (('fast', 10), ('slow', 30),)

    def __init__(self):
        sma_fast = bt.ind.SMA(period=self.p.fast)
        sma_slow = bt.ind.SMA(period=self.p.slow)
        self.crossover = bt.ind.CrossOver(sma_fast, sma_slow)

    def next(self):
        if self.crossover > 0:
            self.buy()
        elif self.crossover < 0:
            self.sell()

cerebro = bt.Cerebro()
cerebro.addstrategy(SmaCross)
cerebro.run()
```

### 2.3 Zipline

**定位**：Quantopian 開源的 backtesting engine

**優點**：
- 機構級代碼質素
- 支援 Pipeline API（factor 研究）
- Event-driven
- 完整的 risk 分析

**缺點**：
- Quantopian 已結業，維護減少
- 安裝 dependency 複雜
- 主要支援美股

**適用場景**：Factor 研究、美股策略

## 3. Reinforcement Learning Framework

### 3.1 FinRL

**定位**：一站式 financial reinforcement learning framework

**優點**：
- 整合多種 RL 演算法（DQN、PPO、A2C、SAC 等）
- 內置金融 environment
- 支援多種數據源
- 方便重現論文

**缺點**：
- 文件質素參差
- 代碼結構複雜
- 實盤交易支援有限

**適用場景**：RL 策略研究、學術研究

**範例代碼**：
```python
from finrl.agents.stablebaselines3.models import DRLAgent
from finrl.main import check_and_make_directories
from finrl.meta.env_stock_trading.env_stocktrading import StockTradingEnv

# Create environment
env = StockTradingEnv(df=train_data, ...)

# Train Agent
agent = DRLAgent(env=env)
model = agent.get_model("ppo")
trained_model = agent.train_model(model, total_timesteps=100000)
```

---

### 3.2 TensorTrade

**定位**：可組合的 trading environment framework

**優點**：
- 模組化設計
- 支援自訂 component
- 整合 TensorFlow/PyTorch

**缺點**：
- 維護不活躍
- 文件不完整
- 社群細

**適用場景**：自訂 RL environment 研究

---

## 4. Full-Stack Framework

### 4.1 QuantConnect (LEAN)

**定位**：雲端 + 本地的 full-stack 量化平台

**優點**：
- 支援 multi-asset（股票、期貨、外匯、加密貨幣）
- 免費雲端 backtest
- 開源本地部署（LEAN engine）
- 支援實盤交易（需要 broker）
- 多語言（Python、C#）

**缺點**：
- 本地部署複雜
- 雲端資源有限制
- 學習成本較高

**適用場景**：全流程策略開發、multi-asset

---

### 4.2 Freqtrade

**定位**：加密貨幣 trading bot

**優點**：
- 專注加密貨幣
- 支援多個交易所
- 內置 backtest + 實盤交易
- Docker 部署簡單
- 社群活躍

**缺點**：
- 只支援加密貨幣
- 策略表達有限制

**適用場景**：加密貨幣自動化交易

## 5. Framework 選擇決策樹

```
What is your main goal?
│
├─ Quickly validate strategy ideas
│   └─ VectorBT (fastest)
│
├─ Complex strategy development
│   └─ Backtrader (flexible)
│
├─ Factor research
│   └─ Zipline + Alphalens
│
├─ Reinforcement learning research
│   └─ FinRL (most complete)
│
├─ Crypto live trading
│   └─ Freqtrade (out-of-box)
│
└─ Multi-asset + live trading
    └─ QuantConnect LEAN
```

## 7. 實用建議

1. **初學者**：由 Backtrader 開始，理解 event-driven 架構
2. **快速迭代**：用 VectorBT 做 parameter sweep
3. **RL 研究**：FinRL 提供完整的起點
4. **生產系統**：考慮 QuantConnect LEAN 或自行建構
5. **加密貨幣**：Freqtrade 係最容易的選擇
