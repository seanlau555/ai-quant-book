## 22.1 核心洞察總結

### 五個最重要的洞察

| # | 洞察 | 來源 | 為何重要 |
|---|------|------|----------|
| **1** | 預測 ≠ 盈利 | 第 9、10 課 | 好的預測也可能因成本、execution、風險控制而虧損 |
| **2** | 一個模型無法在所有市場中都表現出色 | 第 1、11 課 | 這是 multi-agent 的根本原因 |
| **3** | 風險控制必須獨立並擁有否決權 | 第 15 課 | LTCM 和無數案例已證明這點 |
| **4** | Backtest ≠ 實盤交易 | 第 7 課 | Backtest 只是一道篩選，不是神諭 |
| **5** | 系統會衰退，必須進化 | 第 17 課 | 靜態系統的壽命有限 |

### Multi-Agent 思維模型

```
Not "one omnipotent model," but "expert collaboration"

+-------------------------------------------------------------+
|                                                             |
|    Problem Decomposition -> Expert Division -> Coordinated  |
|                             Decision -> Unified Execution   |
|                                                             |
|    Regime      Signal      Risk        Execution            |
|    Agent       Agent       Agent       Agent                |
|                                                             |
|    "What       "What       "Is this    "Execute this        |
|    market      should      safe?"      trade optimally"     |
|    is this?"   we do?"                                      |
|                                                             |
+-------------------------------------------------------------+
```

### 關鍵公式回顧

| 公式 | 含義 | 課程 |
|------|------|------|
| **實盤回報 = 策略回報 - 成本 - Slippage - Impact** | 成本決定你能否盈利 | 第 2、18、19 課 |
| **Kelly: f* = (pb - q) / b** | 最佳倉位取決於勝率和賠率 | 第 15 課 |
| **IC = corr(預測, 實際)** | Information coefficient 衡量預測質素 | 第 9 課 |
| **Sharpe = (回報 - 無風險利率) / Volatility** | 風險調整後回報 | 第 3 課 |
| **淨價值 = 回報改善 - 切換成本** | 評估 Regime Detection 的價值 | 第 12 課 |

## 22.2 常見誤區清單

### 完成本課程後，你不應再犯以下錯誤：

| 誤區 | 正確理解 | 課程 |
|------|----------|------|
| 「Backtest 年化 50%，實盤一定賺錢」 | Backtest 只是篩選，必須扣除成本並通過 OOS | 第 7 課 |
| 「模型準確率 60% 很厲害」 | 準確率不等於盈利，需要看 IC 和成本 | 第 9 課 |
| 「Deep learning 一定比簡單模型好」 | 複雜模型更易 overfit，應由簡單開始 | 第 9 課 |
| 「分散投資就是買很多隻股票」 | 高度相關的股票不是真正的分散 | 第 16 課 |
| 「止蝕會減少回報」 | 不止蝕可能減少本金 | 第 15 課 |
| 「策略做好了，不用管理」 | 市場會變，策略必須進化 | 第 17 課 |
| 「LLM 可以直接交易」 | LLM 是研究助手，不是交易員 | 第 14 課 |
| 「代碼跑得起來就夠了」 | 跑得起來 ≠ 可靠，運維是系統的一部分 | 第 20 課 |

### LLM 的界線：能做甚麼，不能做甚麼

「LLM 可以直接交易」這個誤區值得明確劃出界線。LLM 是強大的研究工具，但絕不能置身於 execution 路徑之中：

| LLM 可以 | LLM 不可以 |
|----------|------------|
| 解析 10-K 文件中的訴訟風險 | 生成交易訂單 |
| 偵測業績電話會議中管理層的語氣變化 | 計算 position size |
| 標示財務報表中的會計異常 | 修改風險參數 |
| 生成因子假設（AlphaAgent） | 執行交易 |
| 彙整多個來源的宏觀研究 | 作出對 latency 敏感的實時決策 |
| 識別與 regime 相關的新聞事件 | 取代量化風險模型 |

> **設計原則**：LLM 的輸出是**人手審核或確定性 agent 的輸入**，絕不能直接驅動操作。LLM 可以提示某份 10-K 文件含有不尋常的訴訟措辭，但是否調整 exposure，由運行確定性、可審計代碼的 Risk Agent 決定。這種分離並非可選項，而是安全邊界。

### 生產基準：學習項目 vs. 生產目標

在追求技術深度之前，先了解學習項目與生產系統之間的性能差距：

| 指標 | 學習項目 | 生產目標 |
|------|----------|----------|
| Risk check latency | ~10ms (Python) | <1ms (Rust) |
| 訂單提交 | ~100ms (REST) | <10ms (gRPC) |
| Backtest 速度 | 每年數據需數分鐘 | 每年數據需數秒 |
| Fill rate | N/A（模擬） | >94% |
| 數據新鮮度 | 日終（Yahoo） | 實時 L1/L2 |
| Uptime | 手動啟停 | 99.9% 自動化 |

這些差距不是令人氣餒的理由，而是一份路線圖。第 21 課的學習項目驗證的是你的**策略邏輯**。縮窄性能差距是工程上的工作，須在策略驗證之後進行，而不是倒過來。

## 22.6 最後的建議

### 關於風險

> **你會虧錢。問題只在於虧多少，以及你能否從中學習。**

- 第一次實盤交易的虧損是學費，不是失敗
- 控制單筆交易的虧損，讓自己有足夠的學習機會
- 切勿動用你輸不起的資金

### 關於複雜度

> **最好的系統往往不是最複雜的。**

- 由簡單開始，先把簡單的事情做好，才增加複雜度
- 每增加一個組件，問問自己：這真的有必要嗎？
- 如果規則可以解決，就不要用 machine learning

### 關於耐心

> **量化交易是一場馬拉松，而不是短跑。**

- 三個月 backtest、三個月 paper trading、三個月小資金 - 至少九個月後才正式開始
- 策略需要時間驗證，不要因為一兩個星期表現不佳就放棄
- 同樣也不要因為一兩個星期表現極佳就加大倉位

### 關於持續學習

> **市場在變，你也必須改變。**

- 今天有效的策略，明天可能失效
- 持續關注市場變化和新技術
- 保持謙遜，承認自己不知道的比知道的更多
