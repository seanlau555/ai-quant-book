# 附錄 B：量化系統的 12 種典型死亡方式

> **入門課程教你如何賺錢；進階課程教你如何死亡。**

---

## 為何要學習「如何死亡」

在機構的量化培訓中，有一條不成文的規矩：

> 新人入職的第一個星期，要學習公司歷史上的失敗案例。

原因很簡單：
- 成功的策略各有各的特質
- 失敗的策略往往死於同樣的幾個原因
- 知道如何死亡，有助你設計出不會死的系統

本附錄總結了 12 種最常見的量化系統死亡方式，每種均包含定義、真實案例和預防措施。

> 注：有具體機構/事件名稱的案例屬公開事件；沒有具體出處的案例是用來解釋機制和風險模式的合成示例。

---

## 死亡方式 1：數據污染死亡

### 定義
系統使用錯誤、缺失或被污染的數據，導致信號失真。

### 典型症狀
- Backtest 表現極佳，實盤突然虧損
- 策略行為由某一天起變得異常
- 信號與市場完全相反

### 案例（示例）
> 2018 年，某團隊的策略突然開始大幅虧損。調查發現數據供應商在更新後把所有價格除以 100（本應是日圓，卻被誤標為美元）。系統以為價格暴跌 99%，於是大舉做多。

### 預防措施
```
[ ] Data quality check pipeline (outliers, missing values, jump detection)
[ ] Multi-source cross-validation
[ ] Real-time vs. historical data consistency checks
[ ] Data change alert mechanism
```

## 死亡方式 2：Overfitting 死亡

### 定義
策略在歷史數據上過度優化，記住的是噪音而非信號。

### 典型症狀
- Backtest Sharpe > 3，實盤 Sharpe < 0.5
- 在不同歷史時期得出截然不同的結果
- 參數稍作調整，回報就劇烈變化

### 案例（示例）
> 一個 ML 團隊用 200 個 feature 訓練模型，backtest 年化回報 80%。實盤第一個月就虧損 15%。事後分析發現，模型學到的是「每月第三個星期二買入科技股」 - 純粹是歷史巧合。

### 預防措施
```
[ ] Strict out-of-sample testing (OOS)
[ ] Limit feature/parameter count
[ ] Cross-validation + Walk-forward analysis
[ ] Maintain skepticism of "too perfect" backtests
```

## 死亡方式 3：Regime Drift 死亡

### 定義
市場 regime 發生根本改變，但策略仍按舊 regime 運作。

### 典型症狀
- 以往有效的策略突然失效
- 連續虧損超過歷史最大 drawdown
- 信號方向持續與市場趨勢相反

### 案例（示例）
> 2020-2021 年，不少 value factor 策略持續虧損。原因是零利率環境下，成長股大幅跑贏價值股。堅守 value 策略的基金出現 50% 以上的 drawdown。

### 預防措施
```
[ ] Regime Detection module
[ ] Rolling correlation monitoring between strategy returns and benchmark
[ ] Multi-strategy, multi-factor diversification
[ ] Regularly review if strategy assumptions still hold
```

---

## 死亡方式 4：Execution 失真死亡

### 定義
Backtest 假設與實盤 execution 之間存在系統性偏差。

### 典型症狀
- 實盤回報遠低於 backtest
- Slippage 遠超預期
- 訂單經常無法成交

### 案例（示例）
> 一個高頻策略 backtest 年化回報 200%。實盤時發現：backtest 假設在最佳買賣盤成交，實際上由於 latency，成交在第三檔。這 0.1% 的差異，經過 10,000 筆交易，吞噬了所有利潤。

### 預防措施
```
[ ] Conservative cost assumptions (slippage, impact, latency)
[ ] Backtest with tick data, not candles
[ ] Small capital live sampling to calibrate backtest model
[ ] Distinguish "predictable Alpha" from "capturable Alpha"
```

---

## 死亡方式 5：風險控制失效死亡

### 定義
風險控制規則存在漏洞、被繞過或沒有執行。

### 典型症狀
- 單筆交易虧損超出門檻
- Portfolio drawdown 觸發 circuit breaker，但系統沒有反應
- 止蝕單沒有執行

### 真實案例（公開事件）
> 2012 年，Knight Capital 因軟件 bug 導致訂單失控，在 45 分鐘內虧損 4.4 億美元。風險控制本應攔截異常訂單，但該 bug 繞過了檢查。

### 預防措施
```
[ ] Risk control completely independent from strategy
[ ] Multi-layer risk control (position, portfolio, system)
[ ] Risk control cannot be bypassed by anyone (including founders)
[ ] Regular risk control drills (deliberately trigger circuit breaker)
```

---

## 死亡方式 6：流動性蒸發死亡

### 定義
需要離場時，卻發現市場沒有流動性。

### 典型症狀
- 止蝕單無法執行
- Slippage 遠超正常水平
- 被迫以極差的價格平倉

### 真實案例（公開事件）
> 2015 年 8 月 24 日，美股「閃崩」。許多 ETF 價格瞬間下跌 20-30%，market maker 撤出造成流動性真空。止蝕單的成交價遠低於預期。

### 預防措施
```
[ ] Avoid concentrated positions in single assets
[ ] Monitor order book depth, not just price
[ ] Extreme scenario liquidity stress tests
[ ] Maintain cash reserves for margin calls
```

---

## 死亡方式 7：相關性飆升死亡

### 定義
危機中資產相關性趨近於 1，分散投資失效。

### 典型症狀
- 「分散」的 portfolio 全面暴跌
- 所有策略同時虧損
- 對沖失效

### 真實案例（公開事件）
> 1998 年 LTCM 危機。俄羅斯債務危機後，其「互不相關」的策略同時虧損。所有套利策略面對同樣的流動性緊縮，相關性由 0.2 飆升至 0.95。

### 預防措施
```
[ ] Stress tests use "crisis correlation" (assume correlation -> 1)
[ ] Maintain truly uncorrelated assets (like treasuries, gold)
[ ] Actively reduce risk exposure on crisis warnings
[ ] Leverage multiples consider crisis scenarios
```

## 死亡方式 8：槓桿爆倉死亡

### 定義
槓桿過高，令一次不利的波動就足以摧毀本金。

### 典型症狀
- 無法滿足 margin call
- 被強制平倉
- 本金虧損超過 50%

### 真實案例（公開事件）
> 2021 年，Archegos Capital 以 5 倍槓桿押注少數幾隻股票。當股價下跌 30%，觸發 margin call 和強制平倉。最終虧損約 200 億美元。

### 預防措施
```
[ ] Leverage limit (recommend < 2x)
[ ] Volatility-adjusted leverage (reduce during high vol)
[ ] Maintain 50% margin buffer
[ ] Stress test: assume volatility doubles
```

---

## 死亡方式 9：人為干預死亡

### 定義
人手干預系統決策，造成更大的虧損。

### 典型症狀
- 手動取消止蝕單
- 向虧損倉位加注以「攤低成本」
- 憑感覺推翻系統信號

### 案例（示例）
> 一位基金經理見到自動系統即將止蝕，心想「市場很快會反彈」，手動取消了止蝕。市場繼續下跌 20%。事後計算顯示，止蝕本可避免 80% 的虧損。

### 預防措施
```
[ ] Strict operating procedures (dual confirmation)
[ ] Manual intervention requires written justification and approval
[ ] Post-mortem review of all manual intervention results
[ ] If manual intervention win rate < 50%, prohibit intervention
```

---

## 死亡方式 10：系統故障死亡

### 定義
技術問題令系統無法正常運行。

### 典型症狀
- 訂單提交失敗
- 市場數據 feed 中斷
- 系統崩潰或延遲

### 真實案例（公開事件）
> 2012 年 Facebook IPO 當日，NASDAQ 交易系統故障。許多訂單未被正確處理，投資者不知道自己買了多少股。索賠金額超過 5 億美元。

### 預防措施
```
[ ] High-availability system design (primary-backup switch)
[ ] Real-time health monitoring and alerts
[ ] Safe mode during failures (can only close positions)
[ ] Regular disaster recovery drills
```

---

## 死亡方式 11：監管變化死亡

### 定義
法律變更令策略不可行或變成違法。

### 典型症狀
- 某些類型的交易被禁止
- 稅務政策改變利潤計算
- Margin 要求提高

### 案例（示例）
> 2010 年後，許多國家禁止或限制無備兌沽空。許多依賴沽空的 neutral 策略不得不調整或結束。2021 年中國對教育行業實施限制後，相關股票暴跌，許多持倉策略虧損 90% 以上。

### 預防措施
```
[ ] Diversify strategy types and regions
[ ] Monitor regulatory developments
[ ] Avoid over-reliance on single policy environment
[ ] Reserve buffer period for regulatory changes
```

---

## 死亡方式 12：對手方適應死亡

### 定義
市場參與者學會了你的策略，並與你對着幹。

### 典型症狀
- 策略回報逐漸衰減
- 似乎總有人搶先於你交易
- 以往有效的信號變得無效

### 案例（示例）
> 某基金以穩定的mean reversion策略聞名。對手方發現這一點後，在預期該基金會買入的位置搶先買入，推高價格；待該基金買入後再沽出。原本 1% 的 alpha 逐漸變成 -0.5%。

### 預防措施
```
[ ] Diversify signal sources and trading times
[ ] Avoid fixed pattern trading
[ ] Monitor strategy capacity and marginal returns
[ ] Continuously develop new strategies to replace decaying ones
[ ] Mind information security (don't reveal strategy details)
```

## 每週健康檢查清單

```
[ ] Data quality check passed
[ ] Regime state normal
[ ] Execution slippage within expected range
[ ] Risk control thresholds not triggered
[ ] Liquidity indicators normal
[ ] Correlation matrix no anomalies
[ ] Leverage within limits
[ ] No abnormal manual intervention
[ ] System health 100%
[ ] No regulatory changes
[ ] Alpha decay within expected range
[ ] Out-of-sample performance matches expectations
```

---

> **請記住**：量化系統不是「設定後就不用理」。它們需要持續 monitoring、定期審計和不斷進化。知道如何死亡，有助你活得更久。
